**Markdown output format (template):**

The log file must use French section headers for consistency with the rest of the project:

- `# Log d'Execution Pipeline` as the main title
- `## Parametres d'Entree` for input parameters table
- `## Etapes du Pipeline` for pipeline steps
- `## Erreurs Rencontrees` for errors
- `## Solutions Appliquees` for solutions

Each step rendered as: `### {N}. {step_name} -- {OK|ECHOUE|INTERROMPU} ({duration:.2f}s)`

If result dict provided, render as bullet list under the step heading.

Error entries include context key-values and optional traceback in a fenced code block.

Status header values: "OK" (no errors), "ERREURS" (some errors but completed), "ECHOUE" (critical failure).

**Important details:**
- Use `time.perf_counter()` for duration measurements (not datetime subtraction -- perf_counter is monotonic and more precise)
- The `write_log()` method must create the logs subdirectory if it does not exist (use `mkdir(parents=True, exist_ok=True)`)
- Log file name: `{YYYYMMDD_HHMMSS}_pipeline.md`
- The class should be safe to use even if `write_log()` is never called (no side effects until write)
- Handle edge cases: step started but never ended (mark as "INTERROMPU"), no steps logged
- Keep the module pure library (no global state, no prints)

Modify `src/gendoc/mcp/server.py` to use PipelineLogger in the key MCP tools that form the /gendoc-full pipeline.

**Strategy:** Use a module-level `_current_logger` variable that gets created when `analyze_devis` is called (the first step of any pipeline) and gets finalized when `generate_slides` completes (the last step). This avoids requiring the MCP client to manage logger state.

**Changes to server.py:**

1. **Add imports at top:**
```python
import traceback
from gendoc.utils.pipeline_logger import PipelineLogger
```

2. **Add module-level state:**
```python
_current_logger: PipelineLogger | None = None
OUTPUT_DIR = PROJECT_ROOT / "Delagrave" / "output"
```

3. **Modify `analyze_devis` tool:**
   - At the start of the try block, create a new PipelineLogger: `_current_logger = PipelineLogger(OUTPUT_DIR)`
   - Call `_current_logger.set_input_params(pdf_path=str(path))`
   - Start step: `step = _current_logger.start_step("Analyse PDF")`
   - On success: `_current_logger.end_step(step, result={"references": len(result.get("references", [])), "revetements": len(result.get("revetements", [])), "speciaux": len(result.get("speciaux", [])), "forfaits": len(result.get("forfaits", [])), "inconnus": len(result.get("inconnus", []))})`
   - Also log input params: `_current_logger.set_input_params(codes_extraits=[r["code"] for r in result.get("references", [])], devis_header=result.get("header", {}))`
   - On exception: `_current_logger.fail_step(step, str(e), traceback_str=traceback.format_exc())`
   - Use `global _current_logger` at start of function

4. **Modify `preview_generation` tool:**
   - If `_current_logger` exists, start step "Preview generation"
   - On success: end step with result summary (total_products, estimated_pages, families count)
   - On exception: fail step

5. **Modify `generate_slides` tool:**
   - Use `global _current_logger` at start of function
   - If `_current_logger` exists:
     - `_current_logger.set_input_params(product_codes=product_codes, output_path=str(output), devis_info=devis_info)`
     - Start step "Generation PPTX"
     - On success: end step with result summary (slides_generated, total_pages, revetements_added count, skipped count)
     - For each skipped product, call `_current_logger.log_error(f"Produit ignore: {s['code']}", context={"code": s["code"], "reason": s["reason"]})`
     - On exception: fail step with traceback
   - **After success or failure**, ALWAYS call `log_path = _current_logger.write_log()` and add `"log_path": str(log_path)` to the returned JSON result
   - Then set `_current_logger = None` (reset for next pipeline run)

6. **Modify `open_sp_selector` tool:**
   - If `_current_logger` exists, start step "Selection SP (HTML)"
   - On success: end step with sp_count
   - On exception: fail step

7. **Modify `load_sp_selection` tool:**
   - If `_current_logger` exists, start step "Chargement selection SP"
   - On success: end step with custom_products count
   - On exception: fail step

**Important:** All logger calls must be wrapped in `if _current_logger:` guards so tools work fine standalone (without a preceding analyze_devis call). Use `global _current_logger` in each function that modifies it.

**Do NOT change function signatures or return types** -- only add logging instrumentation inside existing try/except blocks.

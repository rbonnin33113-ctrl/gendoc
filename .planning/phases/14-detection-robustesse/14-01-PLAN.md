<objective>
Harden devis PDF detection by filtering common false positives through an exclusion list and logging truly unknown codes for review.

Purpose: Current devis analysis lets many non-product strings (measurement values like 850MM, section words like LIVRAISON, SALLE) slip into the "inconnus" list, creating noise. Users and AI reviewing pipeline output cannot distinguish real missing products from garbage. This plan fixes that by: (1) creating an exclusion list of known non-product words, (2) filtering them during classification, (3) logging genuinely unknown codes individually in the pipeline log for later catalog expansion.

Output: Updated devis_analyzer.py with exclusion filtering, MCP server with unknown code logging, and tests proving the behavior.
</objective>

2. In `classify_codes()`, replace the existing hardcoded check (`if code in ['FORFAITS', 'PAILLASSE', ...]`) with a check against EXCLUSION_WORDS. The logic should be:

   - This is a "silent filter" -- excluded words simply disappear from the output, they are not products, not forfaits, not unknowns.

3. Also add pattern-based exclusion in `classify_codes()` for measurement values that match `\d+MM$` or `\d+M$` patterns (catches values like "850MM", "1200MM" even if not explicitly listed). This goes right after the EXCLUSION_WORDS check.

4. Keep the existing `extract_article_codes()` filters as-is (they filter at PDF extraction level). The EXCLUSION_WORDS filter operates at the classification level in `classify_codes()`, providing a second defense layer.

Important: Do NOT modify `extract_article_codes()` -- the exclusion logic belongs in `classify_codes()` because that function has the context to distinguish between "known non-product" (exclude) vs "genuinely unknown" (keep in inconnus). The extraction function should remain permissive.

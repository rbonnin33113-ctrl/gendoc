  <files>src/gendoc/parsers/md_writer.py</files>
  <action>
Create `src/gendoc/parsers/md_writer.py` as the write counterpart to `md_parser.py`. This is a pure library module (no I/O side effects, no print). It must produce MD content in the EXACT format that `md_parser.parse_family_md()` can parse back.

**Study the format from paillasse.md carefully.** The product section structure is:

```
## {CODE}

| Champ | Valeur |
|-------|--------|
| code | {code} |
| ref | {ref} |
| titre | {titre} |
| famille | {famille} |

### Texte

{texte}

### Dimensions

| Dimension | Valeur | Prefix | Shape Index |
|-----------|--------|--------|-------------|
{dimension rows}

### Images

| Position | Chemin | Chemin Original | Left | Top | Width | Height | Shape Index |
|----------|--------|-----------------|------|-----|-------|--------|-------------|
{image rows}

### Metadata PowerPoint

| Champ | Type | Prefix | Shape Index |
|-------|------|--------|-------------|
{metadata rows}

---
```

**Functions to implement:**

1. `format_product_section(product: dict) -> str`
   - Takes a product dict (same schema as md_parser output: code, ref, titre, famille, texte, dimensions, images, metadata_pptx)
   - Returns the complete `## {CODE}` section as a string including the trailing `---` separator
   - titre can be multiline (newlines within the table cell are preserved in MD)
   - Empty lists for dimensions/images/metadata_pptx should still produce the table headers with no data rows
   - This is the core function - if this produces correct output, everything else works

2. `append_product_to_family(filepath: Path, product: dict) -> None`
   - Reads existing family MD file
   - Appends the formatted product section at the end (before any trailing newlines)
   - If file does not exist, creates it with a header:
     ```
     # {Famille}

     > Total references: 1

     ```
     followed by the product section
   - Updates the "Total references" counter in the header (parse the `> Total references: N` line, increment by 1)

3. `write_family_file(filepath: Path, header_lines: list[str], products: list[dict]) -> None`
   - Writes a complete family MD file from scratch (used by update/delete operations in Plan 02)
   - header_lines: the lines before the first `## ` section
   - products: list of product dicts to write

4. `update_header_count(filepath: Path, new_count: int) -> None`
   - Reads the file, finds the `> Total references: N` line, replaces N with new_count, writes back
   - Used after add/delete operations

**Critical constraint:** The output of `format_product_section` must round-trip through `parse_family_md`. Verify this by constructing a product dict, writing it, then parsing it back - the result must match.

**Do NOT** import or depend on md_parser.py at runtime. The writer is a standalone module. The round-trip compatibility is validated by tests (Phase 19), not by runtime coupling.

**Updated signature:**
```python
@mcp.tool()
async def add_reference(
    famille: str,
    code: str,
    titre: str,
    ref: str = "",
    texte: str = "",
    dimensions: str = "[]",
    images: str = "[]",
    metadata_pptx: str = "[]"
) -> str:
```

Note: `famille` (not `family`) to be consistent with the French naming used throughout the codebase. Change the parameter name from the stub's `family` to `famille`. Keep `ref` as optional (default empty string) since CRUD-01 says minimum fields are code + titre + famille. `dimensions`, `images`, `metadata_pptx` are JSON strings (MCP tools receive strings, not complex objects).

**Implementation steps:**

1. **Validate inputs:**
   - `code` must be non-empty after strip
   - `titre` must be non-empty after strip
   - `famille` must be non-empty after strip (lowercase it for file lookup)

2. **Check for duplicates (CRUD-05):**
   - Use `find_product(code, REFERENCES_DIR)` to check if code already exists
   - If exists, return error JSON: `{"error": "Code deja existant: {code}", "famille_existante": "{existing_famille}"}`

3. **Build product dict:**
   - Parse `dimensions` JSON string into list of dicts
   - Parse `images` JSON string into list of dicts
   - Parse `metadata_pptx` JSON string into list of dicts
   - Construct product dict matching md_parser schema

4. **Write to family file:**
   - Family file path: `REFERENCES_DIR / f"{famille.lower()}.md"`
   - Use `append_product_to_family(family_path, product)` from md_writer
   - If family file does not exist, md_writer creates it (new family creation is Phase 17 concern for index updates, but the actual file creation happens here)

5. **Return success JSON:**
   ```json
   {
     "status": "ok",
     "code": "{code}",
     "famille": "{famille}",
     "fichier": "{relative_path}",
     "resume": "Reference ajoutee: {code} dans {famille}"
   }
   ```

6. **Error handling:** Wrap in try/except. On any error, return JSON with `error` key and `resume` key (compact French summary, per v1.3 convention).

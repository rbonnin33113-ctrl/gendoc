Add two new functions to `md_writer.py`. These functions MAY import from `md_parser.py` at runtime (unlike format_product_section which is standalone) because they need to read existing products to rewrite the file.

**1. `update_product_in_family(filepath: Path, code: str, updates: dict) -> dict`**

Strategy: Read-modify-write the entire family file.

Steps:
- Import `parse_family_md` from `gendoc.parsers.md_parser` (local import inside function to avoid circular deps at module level)
- Parse all products from the file using `parse_family_md(filepath)`
- Find the product with matching code (case-insensitive comparison using `.upper()`)
- If not found, raise `ValueError(f"Code non trouve dans {filepath.name}: {code}")`
- Apply `updates` dict to the found product: for each key in updates, overwrite the product's field. Only update fields that are present in updates (partial update). Valid keys: `ref`, `titre`, `texte`, `dimensions`, `images`, `metadata_pptx`. Do NOT allow updating `code` or `famille` (these are structural identifiers).
- If updates contains `code` or `famille`, raise `ValueError("Cannot update code or famille - use delete + add instead")`
- Read the file header (everything before the first `\n## ` section) to preserve it
- Use `write_family_file(filepath, header_lines, products)` to rewrite the complete file
- Return the updated product dict

**2. `remove_product_from_family(filepath: Path, code: str) -> dict`**

Steps:
- Import `parse_family_md` from `gendoc.parsers.md_parser` (local import)
- Parse all products from the file
- Find and remove the product with matching code (case-insensitive)
- If not found, raise `ValueError(f"Code non trouve dans {filepath.name}: {code}")`
- Read the file header to preserve it
- Use `write_family_file(filepath, header_lines, remaining_products)` to rewrite
- After writing, call `update_header_count(filepath, len(remaining_products))` to fix the counter
- Return the removed product dict (useful for confirmation messages)

**Helper needed: `_read_header(filepath: Path) -> str`**

Reads the file and returns everything before the first `\n## ` pattern. This preserves the family name, metadata comments, extraction date, etc. Implementation:
- Read file content
- Split on `\n## ` (same pattern md_parser uses)
- Return the first element (header text) as-is

**Important:** Both functions perform file I/O (read + write). They are NOT pure functions like `format_product_section`. This is acceptable because update/delete are inherently side-effectful operations.

**1. `update_reference` MCP tool (CRUD-03):**

```python
@mcp.tool()
async def update_reference(
    code: str,
    ref: str | None = None,
    titre: str | None = None,
    texte: str | None = None,
    dimensions: str | None = None,
    images: str | None = None,
    metadata_pptx: str | None = None
) -> str:
```

Implementation:
- Validate `code` is non-empty
- Use `find_product(code, REFERENCES_DIR)` to check existence (CRUD-05). If not found, return error JSON: `{"error": "Code non trouve: {code}", "resume": "ECHEC modification: code {code} non trouve"}`
- Build `updates` dict from non-None parameters only. For `dimensions`, `images`, `metadata_pptx`: parse JSON strings into lists.
- If no updates provided (all None), return error: `{"error": "Aucun champ a modifier", "resume": "ECHEC modification: aucun champ specifie"}`
- Determine family file: `REFERENCES_DIR / f"{product['famille']}.md"` (use the famille from the found product, NOT from user input)
- Call `update_product_in_family(family_path, code, updates)`
- Return success JSON:
  ```json
  {
    "status": "ok",
    "code": "{code}",
    "famille": "{famille}",
    "champs_modifies": ["titre", "texte"],
    "resume": "Reference modifiee: {code} ({N} champ(s))"
  }
  ```
- Wrap in try/except for error handling with `error` + `resume` keys

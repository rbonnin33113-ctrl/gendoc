**Logo handling:**

**`add_cover_page(prs, devis_info, logo_path=None)`:**
- Uses a BLANK slide layout (layout index 0 is "Page de garde" in the template, but per user decision we build programmatically — use blank layout from prs.slide_layouts if available, otherwise use the first layout and clear placeholders).
- Adds a blue bandeau rectangle at top (~15% of slide height) and bottom (~8% of slide height) using `MSO_SHAPE.RECTANGLE` with fill color DELAGRAVE_BLUE.
- If logo_path exists and file is found, insert logo image centered in the top bandeau.
- If no logo, add "DELAGRAVE" text in white bold (28pt) centered in top bandeau.
- Center a text box with the project title (from `devis_info.get('titre_affaire', devis_info.get('client', 'Dossier de Fiches Techniques'))`) in large font (24pt), bold, centered on the slide.
- Below the title, add devis info: numero, date, client — in smaller font (14pt), centered, gray color.
- The slide dimensions are A4 portrait (7561263 x 10693400 EMU) — same as existing template.

**`add_chapter_separator(prs, family_name)`:**
- Same visual style as cover page but simpler.
- Blank slide with blue bandeau at top (~12% of slide height).
- Family display name (from FAMILY_DISPLAY_NAMES) in white bold (32pt) centered in the bandeau.
- Optionally a thin blue line below the bandeau for visual flair.
- Rest of slide is white/empty.

**`add_toc_page(prs, toc_entries)`:**
- `toc_entries` is a list of dicts: `[{'family': str, 'family_display': str, 'products': [{'code': str, 'titre': str, 'page_number': int}]}]`
- Uses a blank slide layout.
- Title "Sommaire" at top (24pt, bold, DELAGRAVE_BLUE color).
- For each family: family display name in bold (14pt, DELAGRAVE_BLUE), then for each product: code + truncated title ... page number (11pt, regular), right-aligned page number.
- Build the TOC content as a single text frame with formatted paragraphs (use python-pptx paragraph runs for bold/regular formatting).
- If too many products for one slide, split across multiple TOC slides.

**`assemble_document(prs, product_slides_by_family, devis_info, logo_path=None)`:**
- This is the main orchestrator called after all product slides are generated.
- Takes a Presentation object that already has product slides organized by family.
- **Strategy:** Instead of rearranging existing slides (which python-pptx makes difficult), the assembly function will be called BEFORE product slides are generated. It will:
  1. Add cover page (slide 1)
  2. Add placeholder TOC slide(s) (slide 2+)
  3. For each family in FAMILY_ORDER that has products:
     - Add chapter separator slide
     - (Product slides for this family are added by generate_presentation after this)
  4. After all slides exist, go back and update TOC page numbers.

- The function returns a dict mapping family names to their separator slide indices, so generate_presentation knows where to insert product slides.

Actually, the cleaner approach: **Build the complete document in one pass.**

**`assemble_document(product_groups, prs, devis_info, references_dir, project_root, logo_path=None)`:**
- `product_groups` is an ordered dict: `{family_name: [list of product dicts]}` — already sorted by FAMILY_ORDER.
- Steps:
  1. Add cover page
  2. Add a placeholder TOC slide (blank for now, will be populated at the end)
  3. Track `toc_entries = []` and `page_counter = 3` (cover=1, TOC=2, first content=3)
  4. For each family in FAMILY_ORDER:
     - If family has products in product_groups:
       - Add chapter separator slide, increment page_counter
       - For each product in that family:
         - Add product slide(s) using existing `_populate_slide` and `_insert_images` from pptx_generator
         - Record product code, titre, and page_number in toc_entries
         - Increment page_counter
  5. After all slides: populate the TOC placeholder slide with real page numbers
  6. Return assembly stats

**Sub-grouping for equipement/elec-sorb/complements:**
- Within these families, group products by common prefix in their code (e.g., CU*, FL*, EU* in equipement).
- In the TOC, show sub-group headers. On the chapter separator or within product flow, no additional sub-separator pages — just logical grouping in the TOC.

**Important python-pptx notes:**
- Use `from pptx.util import Inches, Pt, Emu, Cm` for sizing
- Use `from pptx.dml.color import RGBColor` for colors
- Use `from pptx.enum.shapes import MSO_SHAPE` for shape types
- Use `from pptx.enum.text import PP_ALIGN, MSO_ANCHOR` for text alignment
- Text frame paragraphs: `tf = shape.text_frame`, `p = tf.add_paragraph()`, `run = p.add_run()`, `run.text = "..."`, `run.font.bold = True`
- Slide dimensions are on prs.slide_width and prs.slide_height

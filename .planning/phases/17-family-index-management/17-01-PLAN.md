<task type="auto">
  <name>Task 1: Create index_manager.py module</name>
  <files>src/gendoc/parsers/index_manager.py</files>
  <action>
Create a new module `src/gendoc/parsers/index_manager.py` with two public functions:

**1. `ensure_family_infrastructure(famille: str, references_dir: Path) -> dict`**

Called when adding a product to a potentially new family. Does the following:
- Checks if the family MD file exists at `references_dir / f"{famille.lower()}.md"`
- Checks if the images directory exists at `references_dir.parent / "images" / famille.lower()`
- If images directory does not exist, creates it with `mkdir(parents=True, exist_ok=True)`
- Returns a dict: `{"famille": famille.lower(), "md_existed": bool, "images_dir_created": bool}`
- This does NOT create the MD file (that is already handled by `append_product_to_family` in md_writer.py)

**2. `refresh_index(references_dir: Path) -> dict`**

Regenerates the `_index.md` file based on the actual state of family files on disk. Steps:
- Import `get_all_families` and `get_all_family_files` from `gendoc.parsers.md_parser`
- Call `get_all_families(references_dir)` to get `{family_name: count}` dict
- Derive the Type column from the family name. Use a TYPE_MAP dict:
  ```
  TYPE_MAP = {
      'paillasse': 'PPT (texte + dimensions + image)',
      'sorbonne': 'PPT (texte + dimensions + image)',
      'revetement': 'PPT (texte + 2 images)',
      'meubles': 'PPT (texte + image)',
      'tables-en': 'PPT (texte + image)',
      'equipement': 'PPT (images positionnees)',
      'elec-sorb': 'PPT (images positionnees)',
      'complements': 'PPT (images positionnees)',
      'fiches-existantes': 'EXT (fichiers .pptx)',
  }
  ```
  For unknown families (newly created), default to `'PPT (texte + image)'`.

- Derive display name for each family. Use a DISPLAY_MAP dict with the EXACT accented chars from the existing `_index.md`:
  ```
  DISPLAY_MAP = {
      'paillasse': 'Paillasse',
      'sorbonne': 'Sorbonne',
      'revetement': 'Rev\u00e8tement',
      'meubles': 'Meubles',
      'tables-en': 'Tables EN',
      'equipement': 'Equipement',
      'elec-sorb': 'Elec sorb',
      'complements': 'Compl\u00e9ments',
      'fiches-existantes': 'Fiches Existantes',
  }
  ```
  For unknown families, capitalize: `famille.replace('-', ' ').title()`.

- Define a FAMILY_ORDER list to control row ordering in the table. Known families appear in this fixed order. Any new families (not in FAMILY_ORDER) are appended alphabetically at the end (before 'fiches-existantes' which should always be last):
  ```
  FAMILY_ORDER = [
      'paillasse', 'sorbonne', 'revetement', 'meubles', 'tables-en',
      'equipement', 'elec-sorb', 'complements', 'fiches-existantes'
  ]
  ```

- Calculate total references: `sum(families.values())`

- Read the existing `_index.md` first to extract the "Source" and "Extraction" lines so they are preserved (do not hardcode them). Use regex to extract: `r'> Source: (.+)'` and `r'> Extraction: (.+)'`. If not found, use sensible defaults.

- Write `_index.md` with this exact structure (matching existing format):
  ```markdown
  # Index des References Delagrave

  > Source: {preserved_source}
  > Extraction: {preserved_extraction}
  > Total: {total} references dans {nb_families} familles

  ## Familles

  | Famille | Fichier | Nb references | Type |
  |---------|---------|---------------|------|
  {rows}

  ## Structure d'un fichier famille

  Chaque fichier MD contient :
  - En-t\u00eate : nom famille, source, date, compteur
  - Sections `## {Code}` : une par produit
    - Tableau identit\u00e9 : code, ref, titre, famille
    - `### Texte` : contenu descriptif
    - `### Dimensions` : tableau avec valeur, prefix PPTX, shape index
    - `### Images` : tableau avec chemin, position (left/top/width/height), shape index
    - `### Metadata PowerPoint` : mapping complet colonnes -> shapes

  ## Fichiers speciaux

  | Fichier | Role |
  |---------|------|
  | [_index.md](_index.md) | Ce fichier - point d'entree |
  | [_parametrage.md](_parametrage.md) | Config mapping famille -> template PowerPoint |
  ```

  Each family row format:
  ```
  | {display_name} | [{stem}.md]({stem}.md) | {count} | {type} |
  ```

- Return: `{"total": total, "families": nb_families, "families_detail": {name: count, ...}}`

The module should be a pure library (no print/logging). Import only from md_parser (no circular deps).

Modify `src/gendoc/mcp/server.py` to auto-refresh `_index.md` after every successful CRUD operation.

**1. Add imports:**
```python

```

**2. Modify `add_reference` tool:**
- BEFORE calling `append_product_to_family`, call `ensure_family_infrastructure(famille, REFERENCES_DIR)` to create the images directory if this is a new family.
- AFTER the successful `append_product_to_family` call, call `refresh_index(REFERENCES_DIR)` to update _index.md.
- Include infrastructure info in the response: if `images_dir_created` is True, add `"nouvelle_famille": True` to the response JSON.
- Update the resume: if new family was created, append " (nouvelle famille)" to the resume string.

**3. Modify `update_reference` tool:**
- AFTER the successful `update_product_in_family` call, call `refresh_index(REFERENCES_DIR)` to update _index.md.
- No other changes needed (update does not change family membership).

**4. Modify `delete_reference` tool:**
- AFTER the successful `remove_product_from_family` call, call `refresh_index(REFERENCES_DIR)` to update _index.md.
- No other changes needed (counters recalculated by refresh_index).

**Error handling:** If `refresh_index` raises an exception, catch it and add a warning to the response (the CRUD operation itself succeeded, just the index update failed). Example:
```python
try:
    refresh_index(REFERENCES_DIR)
except Exception as idx_err:
    result_dict["warning_index"] = f"Index non mis a jour: {str(idx_err)}"
```

Do NOT let an index refresh failure cause the whole CRUD operation to fail. The CRUD write is the primary operation; index refresh is secondary.

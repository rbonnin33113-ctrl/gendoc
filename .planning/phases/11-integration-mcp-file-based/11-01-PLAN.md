  <name>Task 1: Add open_sp_selector and load_sp_selection MCP tools</name>
  <files>src/gendoc/mcp/server.py</files>
  <action>
Add two new MCP tools to server.py:

**1. open_sp_selector tool:**
- Parameters: `analysis_result: dict` (output of analyze_devis), `output_path: str` (optional, defaults to "output/sp_selector.html")
- Extract `speciaux` list from analysis_result
- If speciaux is empty, return JSON error: "Aucun article special (SP) detecte dans ce devis"
- Call `generate_sp_selector_html(sp_articles=speciaux, references_dir=REFERENCES_DIR, output_path=resolved_path)`
- Resolve relative paths from PROJECT_ROOT (same pattern as generate_slides)
- Return JSON with: output_path (absolute), sp_count, catalog_size, and a message instructing the user to open the HTML file, edit SP articles, export the JSON, then call load_sp_selection
- Add import for `generate_sp_selector_html` from `gendoc.generators.html_sp_selector` at top of file

**2. load_sp_selection tool:**
- Parameters: `json_path: str` (path to the sp_selection.json exported from HTML)
- Resolve relative paths from PROJECT_ROOT
- Validate file exists, return JSON error if not
- Read and parse the JSON file
- Validate it's a list of dicts, each having at minimum 'code' and 'famille' keys
- Return the content as a JSON string (this is the format generate_slides expects for custom_products parameter)
- The returned JSON string can be passed directly to generate_slides's custom_products parameter

Follow existing patterns in server.py: async def, docstring with Args/Returns/Example, try/except with JSON error returns, Path resolution from PROJECT_ROOT.

Run: `python -c "from gendoc.mcp.server import mcp; print([t.name for t in mcp._tool_manager._tools.values()])"` and confirm open_sp_selector and load_sp_selection appear in the list.

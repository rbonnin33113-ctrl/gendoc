  <name>Task 1: Create HTML SP selector generator module</name>
  <files>src/gendoc/generators/html_sp_selector.py</files>
  <action>
  Create `src/gendoc/generators/html_sp_selector.py` with the following:

  **Main function: `generate_sp_selector_html(sp_articles, references_dir, output_path)`**

  Parameters:
  - `sp_articles`: List of dicts from analyze_devis `speciaux` key, each with `{code, famille, prefix, designation}`
  - `references_dir`: Path to Delagrave/references/ (to load catalog)
  - `output_path`: Path where the HTML file will be written

  Logic:
  1. Load the full catalog from references_dir using `parse_family_md()` and `get_all_family_files()`.
     For each product, build a lightweight catalog entry: `{code, ref, titre, famille, texte, dimensions, images}`.
     For images, keep only `{position, chemin}` (the HTML doesn't need pixel coordinates).
     Limit the catalog to essential fields to keep the HTML file manageable in size.

  2. Build the HTML page by string formatting (no Jinja2 dependency needed):
     - Embed `sp_articles` as a JSON variable in a `<script>` tag: `const SP_ARTICLES = [...]`
     - Embed the catalog as a JSON variable: `const CATALOG = [...]`
     - Embed a family list: `const FAMILIES = [...]`
     - Include the full HTML template (see Task 2 for the template specification)

  3. Write the complete HTML to `output_path`.

  4. Return a dict: `{output_path: str, sp_count: int, catalog_size: int}`

  **Helper function: `_build_catalog_json(references_dir)`**

  Returns a list of lightweight product dicts for embedding in HTML. Each product:
  ```python
  {
      "code": "PM-D-H-75",
      "ref": "Ref : FTP PM-D-H-75 2026-3",
      "titre": "PM-D-H-75 - Paillasse murale...",
      "famille": "paillasse",
      "texte": "Ossature acier...",
      "dimensions": [{"name": "Profondeur utile", "valeur": "600"}],
      "images": [{"position": "Emplacement 3D", "chemin": "Delagrave/images/paillasse/PM-D-H-75.png"}]
  }
  ```

  Exclude fiches-existantes family (no standard product data). Exclude products with empty titles.

  **The HTML template** is a multi-line Python string containing the full self-contained HTML page. It uses Python `.format()` or f-string with the JSON data injected. The template implements:

  A. **Header section**: Title "Selecteur d'articles speciaux (SP)", devis info summary.

  B. **SP articles panel** (left side or top, ~40% width on desktop):
     - List of SP article cards, one per SP article
     - Each card shows: SP code (bold), famille badge, designation text (pre-filled from PDF)
     - Each card has a status indicator: "Non configure" (red) / "Configure" (green)
     - Clicking a card selects it for editing in the right panel

  C. **Editor panel** (right side, ~60% width on desktop):
     - **Search bar**: Text input for searching catalog by code or titre (filters CATALOG array client-side). As the user types, show matching products in a dropdown/list (max 20 results). Each result shows: code, titre (truncated), famille.
     - **"Selectionner" button** on each search result: Loads that product's full data into the edit form below.
     - **Edit form** (visible after selecting a base product):
       - "Produit de base: {code}" label showing which catalog product was selected
       - `famille`: Dropdown select with all families (pre-selected from base product)
       - `titre`: Multi-line textarea, pre-filled from base product titre
       - `texte`: Multi-line textarea, pre-filled from base product texte
       - `dimensions`: Table of dimension rows (name + valeur), pre-filled from base product. User can edit valeur fields. No add/remove rows needed (keep base product structure).
       - `images`: Read-only list showing image positions and chemins from the base product. Images stay as-is from the catalog (out of scope to change images per REQUIREMENTS).
       - **"Valider cet article" button**: Saves the edited data for this SP article, marks it as "Configure" in the left panel, moves to next unconfigured SP.

  D. **Export section** (bottom):
     - Shows count: "X / Y articles configures"
     - **"Exporter JSON" button**: Only enabled when all SP articles are configured.
       Generates a JSON file and triggers browser download. The JSON structure is an array of custom_products compatible with `generate_slides`:
       ```json
       [
         {
           "code": "SPMOB-25355",
           "ref": "Ref : ... (from base)",
           "titre": "edited titre",
           "famille": "selected famille",
           "texte": "edited texte",
           "dimensions": [...edited dimensions...],
           "images": [...from base product...],
           "metadata_pptx": [...from base product...]
         }
       ]
       ```
       The filename should be `sp_selection.json`.

  E. **Styling**: Use inline CSS (no external dependencies). Clean, professional look.
     - Light gray background, white cards with shadow
     - Blue accent color for buttons and highlights
     - Responsive: side-by-side on desktop (min-width 900px), stacked on smaller screens
     - Status badges: red for unconfigured, green for configured
     - Search results in a scrollable dropdown

  F. **JavaScript** (all inline, no external dependencies):
     - `renderSPList()`: Renders the SP article cards from SP_ARTICLES + editing state
     - `selectSP(index)`: Highlights an SP card and shows its editor state
     - `searchCatalog(query)`: Filters CATALOG by code or titre (case-insensitive), returns max 20 matches
     - `selectBaseProduct(catalogIndex)`: Loads product data into the edit form
     - `validateArticle()`: Saves current form data for the selected SP article
     - `exportJSON()`: Builds the custom_products array and triggers file download via Blob + URL.createObjectURL
     - State management: Use a simple `editedArticles` object (keyed by SP index) to track which SP articles have been configured and their data.

  Important implementation details:
  - The `metadata_pptx` field must be preserved from the base product (it contains the PowerPoint placeholder mapping needed for generation).
  - The JSON export must include ALL fields that `generate_slides` expects in `custom_products`: code, ref, titre, famille, texte, dimensions, images, metadata_pptx.
  - The `code` field in the export must be the SP code (e.g., "SPMOB-25355"), NOT the base product code.
  - Dimensions in the export keep the base product's `prefix` and `shape_index` fields (only `valeur` is user-editable).
  - Use `JSON.stringify(data, null, 2)` for readable export.
  - Use `encodeURIComponent` for safe filename in download.
  - All text in the UI should be in French.

  The module should have no dependencies beyond the standard library + gendoc.parsers.md_parser.
